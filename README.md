# 狗屎市场

我们在全球管理了8万亿美元资产，甚至在尼日尔市场都获得了丰厚的回报，唯独在A股这个屎一般的市场亏了。

每次当我们建仓完毕，就会有大量的股票突然砸下来，然后我们被迫做t，在多次做t以后，好不容易摊平了成本，以为终于稳定了局面，没想到这个时候，又有大量的预料不到的，不知从哪里出来的股票源源不断的抛出，感觉我们根本买不完！

## 原理

十一档累计跌幅，从上到下是跌超 16% 到跌超 6%。使用严格小于门槛的口径，恰好跌到阈值不计入该档；收益率先统一精度，避免浮点尾差造成误计。

实时计数剔除成交量为 0 或负数、现价/昨收不为有限正数以及价量字段无法正确解析的股票。合法的大幅涨跌仍按原门槛计数。顶部的「有效股票」数量是通过上述过滤后参与统计的股票数。

灰色柱是历史基底，长度按家数比例、沿中轴对齐。数字已经算好，写在 `cache/baselines.json`。

虚线是历次股灾的包络。每一段日期里，各档分别取最大家数，再乘 0.9，连成一条平滑虚线，日期只标到峰值所在月份。各档最大值可以出现在不同时间。曲线经过各档实际宽度，平滑控制点限制在相邻端点范围内。每个交易日只要有一个达到 `min_codes` 唯一股票覆盖的 15 分钟时间点，就算当天覆盖，使用合格 15 分钟收盘相对昨收计算；不要求全天 16 根齐全。缺少某交易日的合格分钟数据时，整段使用日线收盘，日期牌写「日线」，并且不参与灰色柱的取最大。相同股票、相同时间戳的数据不会重复计数，配置不允许重复日期范围。

彩色柱是现在的家数，嵌在灰柱里，从浅跌的绿到深跌的红。实时数可以长过灰柱。柱和虚线是半透明的，好让后面的图透出来。文字和悬停条不透明。悬停某条虚线时，读的是该段跌超 6% 曾经达到的最大家数。

实时行情按 `config.yaml` 中 `quote_hosts` 的顺序逐台尝试标准行情服务器，同一台使用四条连接同时分页。检查回包标识、序号、命令、重复股票、尾页矛盾及过滤前的股票覆盖数。尾页后仍有真实股票会拒绝；真实服务器的非股票越界占位可忽略。连接、握手、分页、解析或覆盖不足时，丢弃本次结果并尝试下一台；一台完整成功后结束本轮。全部地址失败时保留上一帧家数并显示告警，下轮重新从第一台开始。不测速、不随机选址、不连接扩展行情。完整回包但全部股票无有效成交时，正常显示「暂无有效成交」，不误报网络失败。

第一笔回来之前，图表区域显示等待蒙板，顶部设置始终可用；失败时停止转圈，提供「重试」按钮。重试会唤醒轮询器，不并发发起多轮请求。默认每 2 分钟刷新，右上角可下拉选择 1、2、3、4、5 分钟，选择后保存到配置。间隔从上轮请求完成时开始计算，修改间隔会调整当前剩余等待。主题及间隔保存失败会恢复已确认值并提示，旧动画不能覆盖更新的状态。

界面采用 816×530 的紧凑画布，标题靠近上边缘，去掉顶部英文小字和底部说明。窗口首次显示时按实际客户区尺寸在所在显示器的工作区居中，可拖动边缘缩放或最大化。整个界面随客户区等比例缩放并居中，宽高比不同时保留两侧或上下留白。

## 用法

在本目录执行：

```text
py -m app.main
```

行情地址配置示例（顺序即优先级，每个地址可以有自己的端口）：

```yaml
quote_hosts:
  - host: "114.117.72.207"
    port: 7709
  - host: "123.125.108.101"
    port: 7709
  - host: "114.141.177.118"
    port: 7709
  - host: "114.141.177.40"
    port: 7709
quote_timeout: 8
quote_deadline_seconds: 30
quote_min_stocks: 4500
quote_min_coverage: 0.9
```

默认地址为标准行情服务器，按配置顺序连接；项目自行建立连接、分页和解析。`quote_timeout` 是连接及整帧的超时秒数，分片接收不会重置帧时限；`quote_deadline_seconds` 是单站全部握手和分页的总时限，DNS或请求卡住时调用方也会按截止时间退出并关闭已登记连接。整轮最多依次尝试配置的各台服务器。`quote_min_stocks` 是原始唯一股票最少数，`quote_min_coverage` 是相对上次完整快照原始股票数的最低比例，二者取较大值检查。它们不使用价量过滤后的有效数。停止轮询会取消请求，迟到结果不再回调。手改地址和保护参数后重启程序生效。

修改 `crash_windows` 后，在源行情库可读的本机重新生成历史缓存：

```text
py -c "from app.config import load_config; from app.history import recompute_baselines; recompute_baselines(load_config())"
```

程序启动只读取缓存，不连接历史数据库。缓存与当前日期段、覆盖阈值及算法版本匹配，且全部档位、轮廓、来源和覆盖信息校验通过时才会加载。缓存缺失、失效、损坏或基底为零时，界面独立提示原因，不被实时成功覆盖；没有可用比例尺时暂只显示家数。

## 打包

在项目根目录执行：

```text
py -m PyInstaller --noconfirm theBigShitMarket.spec
```

spec 使用单文件、无控制台模式（对应 `-F -w`），并包含 `web` 全部静态资源、默认 `config.yaml` 和最新 `cache/baselines.json`。不要只用 `-F -w app/__main__.py`，这不会自动收集上述资源。spec 还包含本机 Python 3.10.0 所需的字节码扫描修正。

EXE 文件、运行窗口左上角及任务栏使用同一枚大便图标 `web/assets/app.ico`，包含 16–256 像素的多尺寸版本。图标沿用背景图的三层造型与棕金配色，原始透明 PNG 及设计说明见 `web/assets/README.md`。图标随 EXE 内置，单文件启动无需额外复制资源。

输出为 `dist/theBigShitMarket.exe`。exe 启动时从包内读取网页和缓存，无需源数据库；可写配置放在 exe 旁边，保留主题、刷新间隔和已有行情地址列表，历史日期段与包内缓存对齐。单地址配置会转换为 `quote_hosts` 列表，保留原地址为第一优先并补入默认备用地址，移除单地址键。打包前先完成历史重算；重算后重新打包才会更新 exe 内的历史数据。

配置、升级和缓存均先写同目录临时文件，再原子替换；配置的读改写另有跨线程/进程锁，多个窗口保存不会丢失彼此的设置。启动配置错误会显示对话框，运行故障记录在程序旁 `logs/meter.log`，日志滚动保留约 3 MB。
